Fallback behavior (hybrid mode)

Whichever provider is primary, the other is used to patch gaps — never a hard dependency on one source alone:

options_data_provider = "public" (primary = Public.com) ──────────────────────────────────────────────── Public.com chain empty or errors for a ticker/expiration │ ▼ Fall back to yfinance for that chain (fallback events collected → shown as a warning banner in the HTML report) options_data_provider = "yfinance" (primary = yfinance) ──────────────────────────────────────────────── yfinance is missing an expiration Public.com has (e.g. certain monthly chains) → that specific expiration is fetched from Public.com instead │ If PUBLIC_API_KEY is set, delta/theta are also back-filled from Public's greeks endpoint even when the chain itself came from yfinance

Implied volatility & IV Rank — source priority

Per-contract IV: Public.com chain response → Public.com greeks endpoint → yfinance impliedVolatility column IV Rank (ticker-level): True IV Rank (self-recorded history, needs ≥20 daily observations) ↓ not enough history yet HV-Rank proxy (current 20-day HV vs. its own 1-year range)

No provider — yfinance or Public.com — exposes a historical implied-volatility series. Building an IV Rank without one means recording today's IV every run and accumulating the app's own history over time; there is no shortcut to a "real" IV Rank on day one.

What we can't get, from either source

  • Historical implied volatility. Neither provider offers an IV time series — only a snapshot of today's chain. This is the reason IV Rank has to be self-built from daily snapshots rather than fetched directly.
  • Full Greeks. Gamma, vega, and rho are never fetched from any source — only delta and theta (and only when Public.com is available and authenticated).
  • Dividend / ex-dividend data. Not pulled from any provider and not used anywhere in scoring or recommendations — including the covered-call assignment-risk implications of an upcoming ex-dividend date.
  • True real-time / streaming quotes. yfinance quotes carry an inherent, Yahoo-side delay that isn't documented or guaranteed — this is not a live NBBO feed, and there's no websocket/push data path in either provider integration.
  • Analyst ratings or price targets. Not fetched from any source.
  • News or sentiment data. Not fetched from any source.
  • Short interest / borrow rates. Not fetched from any source.
  • Historical options-chain data for backtesting. Provider APIs only expose the current chain. Local raw-chain snapshots (cache/raw_chains/<TICKER>_<CALL|PUT>.csv) only start accumulating history from whenever that logging was added — there's no way to retroactively pull past chains.
  • Order book depth / Level 2 data. Only top-of-book bid/ask is available from either provider — no market depth.
  • Multi-leg / spread quotes. Both providers return single-leg chains only. Any spread (vertical, iron condor, etc.) pricing would have to be assembled locally from single-leg quotes — not currently done anywhere in this codebase.
